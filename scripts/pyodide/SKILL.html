The runnable reference below uses the same code-and-evidence workspace and floating runtime tools as browser-hosted course work.

The first run downloads the pinned Pyodide 0.27.7 core runtime. Shift+Enter runs a cell and selects the next one. Ctrl/Cmd+Enter runs without changing focus. Use Run all 12 cells for the complete progression.

Worker implementation: load the versioned runtime

runtime-loader.js

Resolve assets relative to the worker and reuse one interpreter promise.

Full source
const RUNTIME = Object.freeze({
  pyodide: "0.27.7",
  python: "3.12.7",
  assetRoot: "assets/pyodide/0.27.7/",
});

let runtimePromise;

export function loadRuntime() {
  if (!runtimePromise) {
    runtimePromise = (async () => {
      const baseUrl = new URL(RUNTIME.assetRoot, self.location.href).href;
      const module = await import(`${baseUrl}pyodide.mjs`);
      return module.loadPyodide({ indexURL: baseUrl });
    })();
  }
  return runtimePromise;
}

Worker implementation: preserve all output channels

python-worker.js

The worker keeps one namespace. It captures streams and returns the final expression with its execution count.

Full source
let executionCount = 0;

async function runCell({ source, inputs = {}, profile = "core" }) {
  const pyodide = await prepareRuntime(profile);
  executionCount += 1;
  pyodide.globals.set("__cell_source", source);
  pyodide.globals.set("__cell_inputs", inputs);
  pyodide.globals.set("__execution_count", executionCount);
  return JSON.parse(String(await pyodide.runPythonAsync(EXECUTE_CELL)));
}

self.addEventListener("message", async ({ data }) => {
  const { id, type = "run" } = data;
  try {
    const result = type === "preload"
      ? (await prepareRuntime(data.profile), { ok: true, stdout: "", stderr: "", value: null })
      : await runCell(data);
    self.postMessage({ id, ...result });
  } catch (error) {
    self.postMessage({ id, ok: false, stdout: "", stderr: String(error), value: null });
  }
});

Optional network boundary

network-fetch.js

Direct browser requests use a named origin allowlist. Everything else fails unless the course injects a reviewed relay.

Full source
const BLOCKED_HEADERS = new Set([
  "connection", "content-length", "cookie", "host", "origin", "referer",
]);

function requestHeaders(headers) {
  return Object.fromEntries(
    [...headers.entries()].filter(([name]) => !BLOCKED_HEADERS.has(name.toLowerCase())),
  );
}

export function createCourseFetch({ fetchImpl = fetch, relayUrl, allowedOrigins = [] }) {
  const allowlist = new Set(allowedOrigins);

  return async function courseFetch(input, init) {
    const request = new Request(input, init);
    const target = new URL(request.url, self.location.href);

    if (target.origin === self.location.origin || allowlist.has(target.origin)) {
      return fetchImpl(request);
    }
    if (!relayUrl) throw new Error(`This lesson does not allow ${target.origin}.`);

    const body = ["GET", "HEAD"].includes(request.method)
      ? null
      : Array.from(new Uint8Array(await request.arrayBuffer()));
    return fetchImpl(relayUrl, {
      method: "POST",
      credentials: "omit",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        url: target.href,
        method: request.method,
        headers: requestHeaders(request.headers),
        body,
      }),
      signal: request.signal,
    });
  };
}

The full source includes request serialization and strips browser-controlled headers. It intentionally contains no deployment URL. A lesson must inject both its allowed origins and its course-owned relay.

How the pieces fit into a course page

  1. Vendor the exact runtime files under a versioned, same-origin asset directory.
  2. Create one PythonRunner for the page or interactive-cell group.
  3. Send plain source and plain inputs to the worker. Do not expose PyProxy objects to page state.
  4. Render stdout, value, and stderr separately.
  5. Connect Stop and Reset through the runner controls. Keep core as the default, switching to network only for a named exercise.

Reference and distribution boundary

The behavior above was synthesized from the task-supplied local reference files vendor-pyodide.mjs, python-worker.ts, client.ts, proxy-fetch.ts, and coding-harness-chat.ts. No reference file, runtime binary, wheel, or deployment URL is copied into this course contribution.

This cookbook page fetches its pinned core runtime only after the reader selects Run. The repository does not copy that runtime binary or any Python wheel. Before distributing browser-Python binaries, review every copied component, distribute the applicable notices, generate the SBOM, and run the browser matrix.
