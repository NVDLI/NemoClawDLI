GitLab CI trust-boundary modules

The root CI file contains only approved module includes. Add Python tests under tests/ and register them in the release gate without editing the GitLab workflow.

  • core.yml owns the required gate, builds its Pages candidate on the same worker, verifies the copied candidate, renders every HTML page, and then exposes human review.
  • sca.yml rejects inherited defaults and variables, pins its image, and owns all scanner jobs.
  • privileged.yml runs only trusted default-branch code, so candidate artifacts never receive credentials and CDN preparation carries no AWS authority. Publication uses a root-owned program on the protected devbox runner.

The privileged module stays inside GitLab integration so reviewers can inspect its source. GitHub receives none of its workflow edges, protected environments, credentials, devbox-runner access, or AWS authority.
